# Findings: uncertainty-arbitrated policy ensembles for zero-shot collision-free reaching

Research design v4 (7 Oct 2026), executed 7–23 Oct 2026 on the OVGU Sofja cluster.
Code: branch `paper/phase0` of panda-gym (`revive` line); frozen configuration tagged `paper-frozen` (`0e925a7`).
Change log with the verification of every code change: `CHANGELOG_paper.md`. Analysis outputs: `analysis/out/`.

## Summary

1. **The gap to the thesis is not definitional.** Collision definition and horizon move the validation mean by at most
   ~2.5 pp (G1); the thesis-era training semantics change nothing beyond seed noise (G2).
2. **CrossQ beats the thesis TQC preset** at every update-to-data ratio (G3). Frozen configuration: CrossQ, UTD 0.125,
   batch 256 (48 % validation success over 4 seeds, 1.4 h per run).
3. **Seeds specialize (RQ1, H1b supported).** In-distribution success does not predict OOD success across 20 seeds
   (Spearman |ρ| ≤ 0.17), and on every one of the 12 OOD scenes the seeds' success rates differ (χ², all p < 1e-6).
4. **Ensembles consolidate this (RQ2):** all 20 members with `critic_argmax` or `mean` reach **72 %** test success
   against **48 %** for the validation-selected single policy (+23–24 pp, 95 % CI ≈ ±1.5 pp), robustly across
   collision definitions and horizons.
5. **The design's central arbitration rule does not work:** the minimum-variance ensemble (Eq. 1) gains only
   +0.8 pp [−0.8, +2.5]; it collapses on `narrow_tunnel` (−56 pp). **H2a is not supported**; the policy's own
   uncertainty is not calibrated out of distribution.
6. **Averaging is the practical choice (RQ3):** `mean` matches `critic_argmax` in success but has ~9× lower joint jerk
   (179 vs. 1599 rad/s³; single policies 435). Jerk grows with the member-switching rate (Spearman ρ 0.69–0.78).
7. **Seed diversity is what matters:** snapshot ensembles from one run recover ~40 % of the seed-ensemble gain on test
   and none on validation; mixing training distributions (incl. domain randomization) adds nothing at equal K.

## 1. Setup

- Stack: panda-gym fork + PyBullet, stable-baselines3 / sb3-contrib 2.9, Python 3.13, torch 2.14 (CUDA 12.6 build;
  the GPU nodes' driver supports CUDA 12.4). Training on A30/A40 GPU nodes (gpu01–03 excluded), evaluation on CPU nodes.
- Evaluation harness (`evaluate.py`): shared episodes (seed = base + 1000 · scene index + i, per-episode start-state
  hash checked in every analysis), a fresh environment per episode, per-episode records (outcome, steps, path length,
  jerk, latency, colliding link, ensemble member sequence).
- Scene roles (`panda_gym/scenes.py`):
  - Train: `reachao1–3` (+ DR variants for the cross-distribution population)
  - Validation: `tunnel`, `workshop2`, `industrial`, `bookshelves`, `raised_shelves`, `tabletop`
  - Test: `narrow_tunnel`, `library2`, `workshop`, `library1`, `dynamic_cross_slow`, `dynamic_cross_fast`
- Primary condition: strict collisions, horizon 150 control steps of 40 ms (6 s), 500 episodes per scene
  (200 in the ensemble K-sweeps). Checkpoint per run: the best of its last 5 on validation (separate episode seeds
  from the reported ones).

## 3. Phase 0: re-baseline

**G1 (evaluation only; 3 CrossQ seeds × 5 definitions × 3 horizons × 8 scenes × 200 episodes).** Validation means
12–21 %. Thesis vs. strict definition: +1.2 pp at most; table counted or not: no difference; `thesis_substep` equals
strict, so the whole definitional effect is the step-end check. Horizon 150 → 400: 0–2.4 pp. Far below the design's
20 pp threshold: the gap is not definitional.

**G2 (thesis TQC preset, 3 seeds × {HEAD, thesis} training semantics).** In-distribution 73 % vs. 76 %, validation
0.1–4.8 % for both; evaluation definition < 1 pp. Thesis-era semantics (truncation, live HER penalty) were not what
produced thesis-level numbers; the paper cannot claim continuity with the thesis numbers.

**G3 (UTD {0.125, 0.25, 0.5, 1} × batch {256, 1024} × {TQC preset, CrossQ}, 2 seeds; 4 seeds for the top cells).**

| Cell (6 validation scenes) | Final model, mean of seeds | Best of last 5 | h per run |
|---|---|---|---|
| CrossQ UTD 0.5, b1024 (4 seeds) | 50 % | 53 % | 4.5 |
| **CrossQ UTD 0.125, b256 (4 seeds)** | **48 %** | **58 %** | **1.4** |
| CrossQ UTD 1, b256 (4 seeds) | 44 % | 49 % | 7.6 |
| CrossQ UTD 0.125, b1024 (4 seeds) | 43 % | 57 % | 1.5 |
| TQC thesis preset, all cells (2 seeds) | 20–31 % | 24–37 % | 1.3–6.6 |

No trend with UTD or batch beyond seed noise (seed SD ≈ 10 pp); CrossQ > TQC everywhere. **G4 freeze** (design rule:
cheapest cell within 3 pp of the best): CrossQ, UTD 0.125, batch 256, 16 envs, 1.2 M steps — `configs/paper_frozen.json`.
Exit criterion (~30 % validation) met.

## 4. Single policies (Phase 1–2, RQ1)

20 seeds of the frozen configuration; NEO on the same episodes.

| Policy (strict) | In-distribution | Validation | Test | Test collisions |
|---|---|---|---|---|
| CrossQ seeds, horizon 150 (mean of 20) | 88.9 % | 56.1 % | 48.2 % | 37.6 % |
| CrossQ seeds, horizon 400 | 89.6 % | 56.9 % | 49.5 % | 40.1 % |
| NEO, horizon 150 | 27.6 % | 16.1 % | 8.9 % | 6.1 % |
| NEO, horizon 400 | 71.0 % | 31.4 % | 41.5 % | 7.2 % |

Stratified-bootstrap 95 % CIs (horizon 150): validation 56.1 [52.9, 59.5], test 48.2 [45.8, 50.7]; IQM 59.4 / 53.4.

- **H1a supported:** OOD success ~35 pp below in-distribution.
- **H1b supported:** Spearman ρ between in-distribution and OOD success across seeds: −0.06 (validation), 0.17 (test),
  0.13 (OOD), all p ≥ 0.47. Per-scene χ² tests: the seeds differ on all 12 OOD scenes (all p < 1e-6). Mixed logistic
  model: seed main effect ≈ 0, seed × scene SD 1.30 [1.19, 1.43] (variational) / 1.24 [1.13, 1.37] (posterior mode);
  statsmodels reports non-convergence for both (the seed variance sits at zero) — report the χ² tests as primary.
  Example ranges across seeds: `tunnel` 0–98 %, `workshop2` 8–97 %, `narrow_tunnel` 2–81 %, `workshop` 0–72 %.
- **NEO** (corrected port): 76 % on reachao3 at horizon 400 vs. the thesis' 60.8 % (+15 pp, stop-and-ask 5; reported,
  not tuned). Few collisions, many timeouts; it needs a median of 6.3 s to reach a goal, so it is weak at horizon 150.

| Strategy | workshop | narrow_tunnel | library2 | library1 | dynamic slow | dynamic fast |
|---|---|---|---|---|---|---|
| `critic_argmax` | +83 %* | +12 %* | +17 %* | +10 %* | +12 %* | +8 %* |

Top-5 members by validation (s11, s18, s2, s17, s8): `mean` +17.9 pp, `precision_weighted` +15.8, `min_variance`

- **H2a (Eq. 1 beats the selected single policy): not supported** with all members; weakly with top-5 or horizon 400.

- **H2c (gains saturate with K): supported** — `mean`, test: K 1 → 5 +16 pp (48 → 64 %), K 5 → 20 +7 pp (64 → 71 %).
- Even a random member per step gains +15 pp: part of the benefit comes from mixing members per se.

## 6. Sources of diversity and cost (RQ3)

**Snapshot vs. seed ensembles** (seeds 0–9; last 5 / last 10 checkpoints of one run; 200 episodes per scene):

| Strategy, K | Seed ensemble, test | Snapshot ensemble, test | Seed, validation | Snapshot, validation |
|---|---|---|---|---|
| `mean`, 10 | 69.3 % | 57.4 % | 85.5 % | 56.8 % |
| `mean`, 5 | 64.1 % | 56.1 % | 81.9 % | 52.1 % |
| `critic_argmax`, 10 | 66.4 % | 53.2 % | 77.2 % | 52.1 % |
| `min_variance`, 10 | 49.9 % | 42.9 % | 65.8 % | 44.5 % |

**H3a partly supported:** snapshots recover ~40 % of the seed-ensemble gain on test (+9 vs. +21 pp over single
policies) at 1/K of the training cost, and none on validation.

**Jerk vs. member switching (H3b supported):**

| | Member switches per step | Mean joint jerk (rad/s³) | Spearman ρ (switch rate, jerk) |
|---|---|---|---|
| single policies | 0 | 435 | |
| `mean` | — (no switching) | 179 | |
| `min_variance` | 0.21 | 851 | 0.78 |
| `critic_argmax` | 0.60 | 1599 | 0.69 |

**Cross-distribution population** (one shared stage-2 checkpoint, 5 fine-tunes each of `reachao3`, `reachao_dr_plr`,
`reachao_dr_adr_plr`, 300 k steps; 400 k steps in total vs. 1.2 M for the main population, so absolute levels are
lower and only relative effects are meaningful):

- Domain randomization does not give better single policies: test 20 % (`reachao3`), 14 % (`dr_plr`), 23 % (`dr_adr_plr`).
- Matched control, equal K, same checkpoint and budget — mixed minus pure-`reachao3`, test:
  K = 3 (20 vs. 10 subsets): `mean` −3.2 pp [−6.2, −0.1], `critic_argmax` −0.4 [−3.0, +2.2], `min_variance` −2.5
  [−4.2, −0.7]; K = 5: −3 to −5 pp (pure groups are single subsets; CIs understate the uncertainty).
- Ensembling within one distribution still helps (pure `reachao3` K = 5: 35 % vs. 20 % single; pure `dr_adr_plr`: 39 %
  vs. 23 %); all 15 members: 40 %.
- **Mixing training distributions adds no diversity beyond seeds**; the recommended recipe is a seed ensemble with
  averaging.

## 7. Engineering findings worth knowing

- **Determinism:** PyBullet's contact-pair order depended on memory addresses and on an environment's history
  (`panda_link1` permanently rubs on the table), so reused environments did not replay an episode seed. Fixed with
  `deterministicOverlappingPairs=1`, a seeded constructor reset (IK-sampled start poses depended on it) and a fresh
  environment per evaluated episode.
- **pybullet API:** `calculateJacobian` takes `localPosition` in the link's URDF frame, not the centre-of-mass frame
  its documentation suggests; pybullet's kinematics are single precision (finite-difference checks need ~1e-3 rad).
- **Cluster:** a SLURM job's working directory can go stale on BeeGFS ("failed to make path absolute"; runners
  re-enter the repository before every Python process); default 64 BLAS threads per process exhausted the per-user
  thread limit on shared nodes (runners set `OMP/OPENBLAS/MKL_NUM_THREADS=1`); gpu01–03 are reserved for other work.
- **Throughput:** ~21 ms per gradient step on the A30 nodes (laptop: 8–10 ms); UTD 0.125 with 16 envs ≈ 250
  env-steps/s, UTD 1 ≈ 45. Seeds on separate GPU nodes run fully in parallel.
- Bugs found and fixed in the analysis (swapped McNemar count labels in `rq2.py`; checkpoint selection tied to the
  stage name) are recorded in `CHANGELOG_paper.md`; no reported number depends on them.

## 8. Limitations and open items

- Simulation only; one robot; hand-designed test scenes (six, two of them dynamic).
- The dynamic scenes' fast level sits at the upper edge of the design's 20–60 % hold-q0 band (52 %); the observation
  has no obstacle velocity (partial observability).
- NEO is a reactive reference with the thesis' gains; no global planner (cuRobo, MπNets) by design.
- The reduced Phase 3 protocol (20 subsets per K, 200 episodes in the sweep); `bayes_sample` not evaluated.
- The cross-distribution population trained 400 k steps; a budget-matched version (~3× the GPU time) would be needed
  to compare its absolute levels with the main population.
- Not yet done: paper figures and the combined results table; nothing is pushed to a remote.
